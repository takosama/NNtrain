# IQ2_M Qwen3.5 LoRA 学習の追加高速化

2026-09-27。対象は `Qwen3.8-27B-Uncensored-noMTP-IQ2_M.gguf`、Intel Arc B580 12 GB × 2、Windows、.NET 10 Release。

## 結果

同じ8更新を旧版と採用版で各2回実行し、平均 **33.120秒 → 18.320秒、1.808倍**。1更新あたり **4.140秒 → 2.290秒**、時間は44.7%短縮しました。旧版は前回の高速化を適用済みの通常リポジトリです。

Attention・DeltaNet・MLPの全496行列、rank8、alpha16、seed1、LR0.0001、gradient clip1、58,363,904学習パラメーターを共通にしています。1会話につき1更新で、会話やトークンを省略していません。ベース重みは凍結し、IQ2_S・IQ3_S・Q4_K等の元の形式のままGPUへ置いています。

旧版の8更新合計は 33.079 / 33.161秒、採用版は 18.365 / 18.275秒。ロード・tokenize・JSON/HTML出力・保存・ハッシュ計算を除く、更新と完了待ちの時間です。各試行は同じ初期アダプターから始め、指定行を順に学習します。OSやドライバーのキャッシュは消去していません。

8更新のLoRA・Adam状態 **175,091,712個のFP32値がビット単位で一致**。全値有限、Adamの二次モーメントは非負、ヘッダーとチェックサムも一致しました。ファイル全体のSHA256は `d70b31afea8ebb923b8b5899855f0be0926e74159673320e60856b6ad35a50ab` です。これは今回の入力列・実機における結果で、任意の入力・GPUでの一致を保証するものではありません。

同じstep8チェックポイントから2更新再開しても、loss・勾配norm・step10のファイル全体SHA256が一致しました。モデル照合済みの保存時間は **1.592秒 → 1.057秒**。初回保存はベースGGUFの照合用ハッシュ計算も含み、旧版11.566秒・採用版11.354秒でした。

## 採用した変更

- 逆伝播でIQ2_S・IQ3_S・Q4_Kの8要素をまとめて復号し、8トークン行で共有。重みをFP32で常駐させず、既存の積和順を保ちます。
- 半精度スケールの変換をGPU命令へ変更。65,536通りのhalf符号を確認しました。
- LoRA勾配は最初の逆伝播で全要素を書き込み、毎更新のゼロクリアを省略。同じ更新内の累積と未使用パラメーターのAdam処理を維持します。
- 全入力トークンのembeddingを1回の転送・カーネルで処理。重複した推論状態の初期化を省略。
- GPUごとの勾配normを先に投入してから結果を回収。計算順は維持。
- 通常学習ではカーネルごとの計時を省略し、キュー4096、再利用バッファ上限2048MiBを採用。loss・更新時間・HTMLは継続して出力します。物理メモリ予算は維持。
- チェックポイントは書き込みと同時にSHA256を計算し、保存後の全量再読み込みを削減。v1形式・既存アダプターとの再開互換性・ディスク確定・一時ファイルの置換を維持。

前向き計算は4行共有を維持しました。8/16行の前向き、16行の8要素転置はこのデータで遅くなったため、既定には採用していません。比較用の実装は実行オプションで選択できます。

## 既存コマンドでの利用

通常リポジトリへ反映・Releaseビルド済みです。学習設定に高速化用の項目を追加する必要はありません。

```powershell
dotnet .\NNtrain.Cli\bin\Release\net10.0\NNtrain.Cli.dll lora --model ".\models\Qwen3.8-27B-Uncensored-noMTP-IQ2_M.gguf" --config .\traning.tuku-lora.json --resume
```

これは既存設定のチェックポイントからの再開コマンドです。現在のつくよみちゃん設定は1536更新を完了しているので、その設定のままでは追加更新しません。今回のベンチマークとCLI確認には別の保存先を使用し、完成済みアダプター・GGUF出力・学習設定のSHA256は変更前と一致しています。

再現用の計測コマンドを追加しました。出力先には未使用のパスを指定します。

```powershell
dotnet .\NNtrain.Benchmarks\bin\Release\net10.0\NNtrain.Benchmarks.dll --qwen35-lora-training-probe --model ".\models\Qwen3.8-27B-Uncensored-noMTP-IQ2_M.gguf" --data .\data\tuku\tuku-qwen35.jsonl --examples "1,2,3,1,241,174,257,512" --options '{"CollectKernelTimings":false}' --output .\training-speed.json --checkpoint .\training-speed-adapter.bin
```

計測用コマンドは既定で詳細なカーネル時間を取得します。上の例では通常学習と同じく無効化しています。旧版は学習時の詳細計時ON・native-half OFFを内部で強制していたため、比較JSONの `Lanes.Options` に実効設定を記録しました。

## 検証

- Releaseビルド成功、警告0・エラー0。
- Qwen3.5 Core: 244成功、失敗0。公開用ソースでも同数成功。
- LoRA・loss表示・ストリーム生成関連 Integration: 43成功、失敗0、CUDA専用6スキップ。
- 通常の `lora` コマンドで別アダプターへ3更新、保存、loss HTMLの3点出力を確認。テスト用実行では自動オープンを無効にし、既存のオープン処理は回帰テストで確認しています。
- 新GPU処理は元の処理とのビット一致、端数行、実モデル幅、バッファ境界、未使用勾配、勾配累積、保存・再開を確認。

今回は3epoch全体の再学習時間、69トークンを超える会話、別GPU、異なるrankでの実27B速度は測定していません。既知の別経路のBF16 optimizer問題には変更を加えていません。
