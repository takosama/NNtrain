# Local Japanese ASR validation, 2026-10-06

Ryzen 5700X, 64 GB RAM, Intel Arc B580 12 GB (device 0), .NET 10 Debug. Existing Release GUI/server processes were preserved. Production recognition uses C# with FP16 host weights and a dedicated OpenCL lane for dense projections; signal preprocessing, convolution and attention use CPU float32 operations. No microphone was opened. No cloud ASR or external LLM API was used.

## Distinct public recordings and official reference

Three Google FLEURS `ja_jp` validation recordings, indices 0/1/2, were converted to mono 16 kHz PCM16. The CPU oracle uses official Transformers 5.18.0 (Nemotron) and NeMo 3.0.0 (Parakeet), CPU PyTorch 2.14.1+cpu, Python 3.13.16 and four CPU threads. Original FP32 and FP16-rounded neural weights with FP32 operations were measured separately. Parakeet's generated signal frontend retains FP32 buffers in the rounded reference, matching C#. NeMo original archive weights were loaded with `weights_only=True`.

For each model, native Arc, official rounded weights and official original FP32 transcripts match after retaining Unicode letters/numbers and removing punctuation/spacing on all three recordings. CER uses the same normalization and edit distance divided by reference character count. These three cases are a small functional comparison, not a broad quality evaluation or evidence that FP16 never changes recognition. A console-encoding misread during investigation incorrectly suggested a Parakeet accuracy improvement; UTF-8 reports confirm that claim was false.

## Numerical parity and corrections

Nemotron's valid 1110 log-mel frames differ from the official processor by maximum 6.77e-5, mean 3.97e-7. Two cached encoder chunks on a 0.57 s prefix differ from the FP16-rounded official CPU reference by maximum 2.47e-6 on native CPU and 2.56e-6 on Arc. Native CPU versus Arc maximum difference is 1.56e-7. Streaming settings are Japanese prompt 10 (`ja-JP`), lookahead 3, first 25 then 32 mel frames, caches reused and padded final chunk decoded completely.

Parakeet parity targets maintained NeMo 3.0.0 rather than assuming every historical NeMo frontend is identical. Corrections exclude the centered terminal frame from normalization, retain it as zero for convolution geometry, use centered constant STFT padding, mask biased invalid intermediate convolution rows and use the valid encoded length. Short frontend maximum error is 4.14e-6; short native CPU encoder maximum is 3.34e-6, Arc 3.10e-6. The full 11.10 s / 139-frame encoder maximum error is 5.01e-6, mean 2.46e-7. Layer traces localized the previous full-input discrepancy to invalid subsampling rows. A small-fixture padding-extent regression protects the correction.

## Memory, interaction and limits

Measured ASR-only dedicated process peaks, including driver allocations, are below 1.36 GB for all six file runs; maximum Parakeet peak is 1,351,294,976 bytes. This meets the 2 GB goal under the tested inputs. FP16 host weights are about 1.28 GB for Nemotron and 1.25 GB for Parakeet. Combined ASR plus an LLM is a separate memory budget.

Nemotron paced 60.5 s file playback delivered 112 changed text updates before stop, first text in 2.730 s, maximum processing lag 0.521 s, final queue empty and stop-to-final 0.343 s. Cancellation, repeated-start rejection and restart passed. It uses cached streaming recognition. Parakeet uses the official model's CTC branch, not TDT. Its global attention preview reprocesses the accumulated utterance every four seconds, is bounded to 30 seconds and may revise earlier text. Its 22.86 s file exceeds real time, and repeated preview is slower still; native CPU convolution/attention are remaining performance work.

Actual Parakeet recognition reached the existing chat composer, preserved typed draft text, allowed final editing and sent the exact edited prompt through the regular Send handler to a mock local HTTP transport. Earlier Nemotron recognition-to-actual-local-LLM evidence exists separately; the latest Parakeet transport test did not start an LLM server. Live WinMM microphone negotiation requests PCM16 48 kHz stereo/mono with 16 kHz fallback and a continuous-history resampler. Physical microphone/device mixing remains unverified because no ambient recording was authorized.
