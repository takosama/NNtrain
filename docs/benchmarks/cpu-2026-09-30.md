## Scope and safety

Baseline HEAD: `c1878e5`. No tracked user modifications were present initially;
existing untracked models, logs, results and checkpoints were preserved. No
reset, pull, commit, push, PR or merge was performed. No applicable AGENTS.md or

model training or model inference was executed by this work.

The existing LoRA process, PID 44852, continued running throughout. Its executable,
configuration, checkpoint and metrics were not written. All builds used new

process command line were read to confirm the environment. Only a failed own

Its reflection lookup bug was corrected; those failed runs are not evidence.

## Changes retained

1. `Tensor.QwenCpu.cs`: RMSNorm square reduction and weighted normalization use
   existing storage-aware Vector256 loads without decoding a whole tensor to a
   new array. Widths below eight retain the original inline scalar loops.
2. SiLU multiply forward and backward use the .NET 10 `Vector256.Exp` operation,
   respecting `Tensor.SimdEnabled`. Inputs below 32 elements use scalar math.
   This uses the runtime exponential, not the repository's restricted-range
   softmax exponential approximation.
3. `TensorStorage.LoadVector256`: signed BFP8 values are read as exactly eight
   bytes, widened with AVX2, converted to FP32 and multiplied by their scale.
   Tensor-wide/single-scale storage avoids scale-index division. Vectors crossing
   block boundaries retain the original per-lane decoder. Non-AVX2 hardware and
   SIMD-disabled execution retain the decoder too. Other storage formats have
   their original early returns.
4. Detached RMSNorm results no longer allocate inverse-RMS storage or a backward
   delegate; detached SiLU results no longer allocate a backward delegate.

RMSNorm backward remains scalar. CPU GEMM, optimizer parallelism, model loaders,
GPU sources and public numeric/storage contracts were not changed.

## Measurement method

Release builds, seeded inputs (`Random(5700)`), CPU-only, one worker,
`DOTNET_TieredCompilation=0`, same inputs/shapes/dtypes per variant. The original
variant uses `git show HEAD` snapshots of both changed pre-existing files and
excludes the new helper. The script builds into unique temporary directories and
refuses to overwrite a result directory.

The matrix suite measures eight rows, widths 1/7/8/9/33/257/2048, four formats,
two operations: 56 records per variant. Each record has 30 warmups and seven
samples of 100 calls. The representative projection suite measures widths
256/1024, rows 1/8, FP32/BFP8, RMSNorm/SiLU/GEMM: 24 records per variant. It uses
three warmups and seven samples of ten calls to limit CPU occupation. Timing
includes result tensor creation/storage conversion; inputs and weights are
constructed outside timing. Allocation is thread-local managed allocation per
call (including a negligible amortized stopwatch allocation), not native or GPU
memory. All means, population SDs and individual samples are retained.

The first run with tiered JIT enabled was unstable and was excluded. Earlier
iterations are retained as raw working evidence, but the final reproducibility
run below is the authoritative complete comparison. Every final file parsed
successfully with all 56 or 24 records; no interrupted result was adopted.

## Final measured results

Source: `benchmark-results/cpu-20260930/reproduction/`.
Times are microseconds per call, mean ± population SD.

| Operation, shape, dtype | Original | Final | Ratio | Allocated bytes original → final |
|---|---:|---:|---:|---:|
| RMSNorm, 8×2048, FP32 | 216.14 ±21.51 | 27.62 ±1.85 | 7.83× | 67,256 → 67,136 |
| SiLU multiply, 8×2048, FP32 | 268.31 ±10.73 | 43.19 ±4.02 | 6.21× | 67,184 → 67,120 |
| RMSNorm, 8×2048, FP16 | 303.03 ±15.16 | 59.00 ±5.87 | 5.14× | 100,048 → 99,928 |
| SiLU multiply, 8×2048, FP16 | 435.21 ±47.97 | 77.77 ±2.03 | 5.60× | 99,976 → 99,912 |
| RMSNorm, 8×2048, BF16 | 243.94 ±1.46 | 66.87 ±1.52 | 3.65× | 100,048 → 99,928 |
| SiLU multiply, 8×2048, BF16 | 317.51 ±21.14 | 80.59 ±2.63 | 3.94× | 99,976 → 99,912 |
| RMSNorm, 8×2048, BFP8 | 408.38 ±19.57 | 72.56 ±2.40 | 5.63× | 83,736 → 83,616 |
| SiLU multiply, 8×2048, BFP8 | 472.08 ±6.17 | 87.31 ±4.22 | 5.41× | 83,664 → 83,600 |
| GEMM, (8×1024) × (1024×1024)ᵀ, BFP8 | 66,713.44 ±956.18 | 11,440.94 ±290.63 | 5.83× | 42,828 → 42,828 |
| Same GEMM, FP32 control | 949.72 ±50.36 | 1,043.53 ±68.80 | 0.91× | 34,540 → 34,540 |

BFP8 GEMM dominates this representative low-precision projection suite. SIMD
decoding reduces arithmetic cost without a full decoded-weight copy or new
allocation. Output storage/conversion still dominates allocations; it is not
correct to call the 120/64-byte savings a large memory reduction.

Concurrent fine-tuning causes substantial noise. Previous complete alternating
profile runs gave original FP32 GEMM 777–1320 µs and changed 773–1044 µs; the FP32
dot implementation uses unchanged direct arrays and bypasses the BFP8 decoder.
One final single-row FP32 control also slowed (92 →185 µs), so no FP32 GEMM speed
claim is made. BFP8 original 63.9–67.4 ms versus changed 11.2–11.4 ms remained
clearly separated. Tiny BF16 SiLU (eight total elements) varied 0.63 →0.73 µs
(changed SD 0.16 µs); this is recorded, not hidden. Small RMSNorm regressions in
an earlier candidate motivated restoring its original scalar loops. A quiet
machine is required to decide effects near these noise levels. Training
throughput was not independently measured, so unchanged throughput is not
claimed. These are kernel/API timings, never whole-model inference ratios.

  PASS. Scalar-only comparisons have zero difference.

## Reproduce

From the repository root, using a new output directory:

```powershell
./tools/cpu-bench/Run.ps1 -IncludeProfile
```

For the existing final binary used here:

```powershell
$env:DOTNET_TieredCompilation = '0'
dotnet "$env:TEMP/nntrain-cpu-final-20260930/CpuBench.dll" --verify
dotnet "$env:TEMP/nntrain-cpu-final-20260930/CpuBench.dll" --matrix
dotnet "$env:TEMP/nntrain-cpu-final-20260930/CpuBench.dll" --profile
$env:DOTNET_EnableHWIntrinsic = '0'
dotnet "$env:TEMP/nntrain-cpu-final-20260930/CpuBench.dll" --verify
Remove-Item Env:DOTNET_EnableHWIntrinsic
```

NuGet sources are cleared for this dependency-free harness; the SDK may still
need read access to user NuGet settings. No packages, GPU capabilities or model
files are needed. Source/build/output paths are printed by the script.

Not performed: GPU tests/probes, whole-model Qwen CPU inference, CPU backend
implementation for the missing Qwen operators, full repository tests with
unaudited GPU fixtures, backward performance profiling, quiet-machine baseline,
multi-worker scaling, full training benchmarks or publication. Next work should
measure block-quantized GEMM and backward kernels before choosing another patch.
