# Qwen GGUF generation optimization — 2026-09-25

## Setup and measurement

- Windows, .NET 10 Release, Intel Arc B580 device 0. One GPU is used.
- Model: `qwen2.5-3b-instruct-q4_k_m.gguf`, 2,104,932,768 bytes.
- SHA-256: `626B4A6678B86442240E33DF819E00132D3BA7DDDFE1CDC4FBB18E0A9615C62D`.
- 36 layers, width 2048, vocabulary 151936. Q4_K/Q6_K payloads remain encoded;
  decoded embedding, activations, K/V and reductions use Float32.
- Prompt: `国会議事堂への行き方を教えて` (9 tokens), greedy sampling.
- Probe measurements exclude model loading and a first warmup with weight upload.
  EOS is disabled in the probe so token counts match. The CLI honors EOS.
- JSON records include options, model and binary hashes, generated IDs,
  transfer/allocation counters and timing. Detailed profiles are separate runs.

The measured total speedup is **116.45×** for this short prompt and generation.
All eight generated IDs match exactly. The reference uses the original serial
quantized kernels, full-prefix forward/full-position head and scalar RMSNorm;
its switches are recorded in `qwen-original-reference-20260925.json`.

At **200 generated tokens**, the final path took **4.126 / 4.091 s** in two
measured runs (48.47 / 48.89 tok/s including prefill; 49.29 / 49.73 tok/s decode).

The user's exact DLL path and mixed-width `--max-new-tokens 1０００` were tested
after deployment. The process generated **1000 tokens in 35.878 s**; loading took
3.884 s, first token 1.702 s including initial weight upload, subsequent decode
averaged **29.23 tok/s**. All 949 captured stdout chunks arrived while the process
was running, and it exited with code 0. Longer decode is slower because attention
reads a growing K/V history; the short-prompt result is not a constant throughput
promise for every context length.

## Profiling and experiments

1. **Reuse K/V; project and download only the last vocabulary row.** The original
   recomputed all positions and downloaded their logits every token. Caching
   plus WG64 cooperative Q4/Q6 kernels reduced eight-token generation to
   794.2 ms (12.3 tok/s decode) while retaining the exact greedy IDs.
2. **Parallel RMSNorm.** The initial optimized profile still spent 14.82 ms/token
   in scalar RMSNorm. A 64-lane reduction reduced that to about 1.10 ms/token.
   At the Q4 subgroup stage, disabling this change reduced decode from about
   48.6 to 29.9 tok/s, measured using the same binary.
3. **SG16 Q4_K.** Two independent output rows per workgroup; each subgroup reuses
   scale/min and packed nibble pairs. The dominant FFN gate/up time fell from
   36.76 to 5.47 ms/token. Subgroup capability checks retain the portable WG64
   path on other devices.
4. **SG16 Q6_K.** Packed low/high bits and 16-value scales are decoded together.
   In separate 31-token decode profiles, Q6 down projection fell from 3.53 to
   1.63 ms/token, and the vocabulary head from 2.23 to 1.00 ms/token.
5. **Subgroup prefill.** Nine-token first-token processing fell from about 208
   to 89 ms. With a 160-token prompt it fell from 2904.8 to 1446.3 ms in a
   same-binary comparison. This path is enabled by default.
6. **Rotate once during cached decode.** Each K is rotated on insertion; the new
   Q is rotated once and reused for all cached positions. Long decode uses device
   scratch rather than exceeding per-workgroup local memory.

GPU timings above include only `gpu-kernel` records. Queue-delay records overlap
and must not be summed as execution time. The final eight-token run retained
2.955 GiB of model allocations after generation and peaked at 3.025 GiB in backend
allocation counters; these are not driver-reported peak VRAM readings.

## Correctness and compatibility

- Release solution build: 0 warnings, 0 errors.
- Qwen/GGUF and tensor operation inventory: **92 passed, 0 skipped**.
- Command parsing, incremental UTF-8, immediate flush, buffered output and NFC
  display consistency: **13 passed, 0 skipped**.
- Independent official gguf-py fixture: **14,361** CPU values bit-exact, including
  F32/F16 boundaries and Q4_K/Q6_K subnormal scales. Original, WG64 and SG16
  matrix paths (decode and prefill) match independently computed float64 results
  within `max(abs(reference)) * 5e-6 + 1e-9`.
- Cached/full-prefix attention and small-model logits, greedy IDs, absolute
  positions, decode beyond 4096, repeat-generation allocation stability, EOS
  and callback-failure cleanup are tested on Arc.
- Tied Q4_K/Q6_K heads reuse `token_embd.weight` payloads. Split GGUFs fail early
  with the `llama-gguf-split --merge` command. USER_DEFINED tokens, NFC and
  supplementary Unicode letters have exact-ID tokenizer regressions.

The user-supplied, unmodified `cl_check (2).py` was additionally run on B580:

This independently checks the primitives, not full pretrained-checkpoint logit
parity with Hugging Face. Prompt prefill still has a 4096-token limit and uses
the original GQA forward kernel. Projections other than Q4_K/Q6_K, including
incompatible 896-wide models, remain explicitly unsupported. This is single-GPU
quantized inference; the existing Transformer training/2GPU routes are separate.

## Reproduce and artifacts

```powershell
dotnet NNtrain.Benchmarks/bin/Release/net10.0/NNtrain.Benchmarks.dll --qwen-generation-probe C:\models\qwen.gguf benchmark-results/new-qwen-run.json --tokens 200 --warmup 1 --runs 2
```

Use `--fast off --cache off --norm off --subgroup off --subgroup-prefill off` for
the original path. Individual switches support controlled A/B. `--profile` adds
kernel/phase/shape timing; output files must be new.
