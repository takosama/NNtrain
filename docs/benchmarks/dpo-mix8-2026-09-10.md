- Legacy non-BFP8 contracts without `bfp8BlockSize` are compatible. `allowPrecisionConversionOnResume: true` explicitly permits precision/block conversion; other identity/objective checks remain strict.

- Final focused validation: Core 43/43 and Integration 47/47, total 90 passed, zero skipped. Includes CPU, CUDA, two-GPU generation, save/resume, precision conversion, legacy contracts and full-DRN output/gradient/lifetime checks. This is not a claim that the entire solution test suite was run.

## Isolated training measurements

Windows / RTX 3070 Ti GPU 0, actual DRN checkpoint `checkpoints/lora/training.forgetmemorydrn-wiki-jp.model.json`: width 512, hidden 1536, 32 layers, vocabulary 11500. Fresh LoRA rank 8 / alpha 16, memoryOutput + ffnInput + ffnOutput. Fixed synthetic token pairs, exact sequence 1024. Chosen/rejected are packed into 2B sequences. Two warmup updates, five measured updates, p50; an extra profiled update is excluded. No generation workers, no production training, no concurrent GPU tests. These short trials do not establish convergence or long-run throughput.

Board memory is sampled immediately after forward, not the maximum over the entire step. Lane allocated bytes include the reusable cache. The final run has 1478.4 MiB active after forward and 260.7 MiB active after backward/update. There are 66,606,316 total parameters including 1,187,840 adapter parameters. Thus parameter count alone does not explain peak memory: layer activations, gradients, temporary operands and CUDA runtime memory dominate. Generation workers add separate replicas not present in this table.

Final vs initial mix8: board memory -844 MiB (-23.9%), short-trial p50 -5.3%. Final vs mix16: board memory -45.6%, p50 +8.8%. No arithmetic/precision/batch change in the lifetime optimization: only private output values that backward never reads are released after their last consumer. ReLU-dependent values and LoRA A/B training inputs remain alive. Full DRN forward/loss/all-gradients tests are exactly equal with retirement enabled/disabled, including nonzero dropout; this is not a long-run convergence guarantee.

Final per-phase medians: reference 187.4 ms, policy forward 133.3 ms, backward 730.4 ms, clip+optimizer 14.2 ms (phase medians need not sum to the total median). The final profiled build reports about 1686 native allocation/release pairs per measured update; these have not all been eliminated. Final raw data: `benchmark-results/dpo-mix8-final-b2-t1024-20260910.json`.

The microbatch-1 trial used only the first (base-output) retirement change and takes roughly 1.5 seconds for two separately updated pairs versus 1.1 seconds for its two-pair trial; this is only an approximate accumulation cost comparison, not an identical optimizer trajectory. Keep production batch 2 / accumulation 8 / slots 4 / queue 8.

## Rejected allocation-pool experiment

Changed detached transient BFP8 outputs' BF16 decode cache from persistent allocation to a reusable lane lease. Unit tests confirmed identical values, versioning, nested-scope lifetime and fewer native allocations. However the full pipeline trial regressed, so the change and its experimental test were removed; this is not part of the final implementation.
