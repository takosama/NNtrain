## 実装したもの

### 1. 丸め順を維持するchunk並列forward

16トークンを1chunkとして、batch×value tile×time chunkを並列実行する。
各chunkの演算本体は従来と同じBF16 Tensor Core operands / FP32再帰更新。
当初候補のWY/GEMMへの数式変換ではなく、境界状態の並列反復で時系列並列性を得る方式を採用。
現行の状態BF16丸めを外したり、近似のまま出力を採用したりしない。

1. chunk境界の推定値をゼロ初期化し、全chunkを並列更新。
2. 次の反復では直前chunkの終了状態を入力とする。
3. 前回から入力境界の全ビットが変わらないvalue tileは、前回結果を再利用。
4. 8回目で全chunkの終了状態が直前の推定値とビット一致するか、GPU上で検査。
5. 一致しなければ、GPU上の条件分岐で元の逐次forwardを実行し、出力と境界状態を上書き。

chunk 0の入力がゼロに固定された依存関係なので、全境界が不動点なら逐次計算の
境界と整合する。入力が変わったchunkだけ再計算する場合も、出力は必ず最新入力に対応する。
検査のためのCPU転送、host同期、動的Graph再captureは追加しない。
減衰が遅い場合は不動点への到達が遅く、fallbackによる追加時間が発生し得る。
512トークン未満では並列反復を使わない。

### 2. 境界保存と再計算/backward融合

- forwardで全時刻の状態を保存せず、16トークンごとの入力状態のみ保存。
- reverse adjointはforward状態に依存しないため、独立した逆向きpassでchunk終端の勾配を計算。
- batch×value tile×time chunkごとに、1 CTA内でforwardを再計算してbackwardを実行。
- 再計算した16トークン分のFP32状態は共有メモリだけに保持し、global memoryへ書き戻さない。
- Q/KのFP32 atomic加算、既存parameter gradientへの加算、非ゼロ終端state gradientの意味を維持。
- 最後の状態更新はbackwardで使わないため省く。DRNのreadはM[t-1]のまま。

## 適用条件とメモリ

- BFP8/mix8_32のDRN学習のみ。K16/32、Vは16の倍数で128以下、sequence>=64。
- V2/V3、他の形状、明示的な旧経路指定、旧ABIでは従来のCUDA計算を使う。
- 1層の境界は最大4 MiB、標準DRNモデルの1 replica/forward合計は最大256 MiB。
  上限を超える層は従来の再計算を使う。
- 現構成は8×2048×32×32×4 bytes = 64 MiBの全履歴に対し、境界は4 MiB/層。
  48層分の境界を保持するため、全層が1枚の履歴scratchを使い回す従来方式より
  モデル全体の所有VRAMは増える。履歴1枚の縮小を「VRAM全体16分の1」とは扱わない。
- bufferはsessionのtransient/event-fenced所有モデルを使用。
  保存contextのDisposeに境界bufferを含め、static永久cacheは追加していない。
- ABI 1.34で3つのchunk exportを追加。旧export、CLI、JSON、checkpoint形式は維持。

## 初期単体比較（採用前の探索結果）

CUDA0、5 warmup + 20 measured、B8/T2048/K32/V32、同じBF16入力。
backwardには非ゼロの既存勾配と終端状態勾配を含めて比較した。

| 案 | 旧版 | 候補 | 判断 |
|---|---:|---:|---|
| 再計算＋backward融合 | 5.691 ms | 2.083 ms | 数値比較合格、学習全体へ統合 |
| 4回反復の並列forward | 2.597 ms | 2.860 ms | 未収束fallback、採用せず |
| 不変chunk再利用＋8回反復forward | 2.604 ms | 0.775 ms | ビット一致、採用候補 |
| 同16回反復forward | 2.386 ms | 0.998 ms | 8回より遅いため選ばない |

初回の全体測定（3 warmup + 10 measured）では、融合のみ830.55 ms、
両方742.23 msのstep中央値。最終A/B統計とは区別する。

最終DLLの通常B8/T2048/K32/V32単体再測定は、forward 2.617→0.771 ms、
再計算＋backward 5.598→2.104 ms、出力/最終状態ビット一致、勾配差1.79e-7。
意図的な遅い減衰（gate=+8、beta=-8）ではforwardがfallbackして2.415→3.423 msと悪化する。
この場合も再計算＋backwardは5.595→2.116 msに短縮、数値は一致する。
したがって並列forward単独の高速化は全ての学習済み重みに対する保証ではない。
`kernel-final.json` / `kernel-final-slow.json` に短系列・端数shapeも含めて記録。
