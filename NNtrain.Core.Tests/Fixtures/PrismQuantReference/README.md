# Prism native quantization reference fixtures

`prism-quant-blocks.json` contains **300 encoded blocks and 38,400 decoded FP32 values**. Each case uses the same `type`, base64 `encoded`, and numeric `decoded` fields as the existing IQ fixtures. All cases represent one 128-element block.

Expected values were obtained by executing the author's **native C dequantizers** in the official Windows CPU release's `ggml-base.dll`; they were not generated by NNtrain or the Python scalar decoder. The script additionally checks native output against an independent scalar implementation **byte for byte**, including signed zeros. Every decoded array has its own raw little-endian FP32 SHA256.

## Format details

| Type | ID | Values | Bytes | Layout |
|---|---:|---:|---:|---|
| PQ2_0 | 142 | 128 | 34 | FP16 `d` at byte 0; 32 packed 2-bit bytes at byte 2 |
| PTQ1_0 | 143 | 128 | 28 | 24 `qs` bytes; 2 `qh` bytes; FP16 `d` at byte 26 |

PQ2 uses `(code - 1) * d`, including the fourth bit pattern: **code 3 decodes as +2 times the scale**. PTQ1 uses byte multiplication modulo 256 before extracting the trit; generic base-3 division does not reproduce its format. PTQ1 has distinct 16-byte, 8-byte and 2-byte lane layouts. These formats are distinct from upstream GGML Q2_0 and TQ1_0.

## Coverage

| Cases | PQ2_0 | PTQ1_0 |
|---|---:|---:|
| Packed-code / byte sweep | 4 | 256 |
| Finite FP16 scale boundaries | 14 | 14 |
| Actual model blocks | 6 | 6 |
| **Total** | **24** | **276** |

- Four PQ2 patterns exercise all four codes at every one of the 128 output positions.
- A 256-block PTQ1 sweep exercises all values 0..255 independently at **every qs and qh byte position**. Position offsets differ, so incorrect output-position mapping is observable. This covers each field's byte values, not all possible combinations of whole blocks.
- Scales include both signed zeros, positive/negative minimum and maximum subnormals, minimum normal, the value immediately below one, one, and maximum finite FP16.
- Six blocks per real model sample `output.weight`, `token_embd.weight`, `blk.0.attn_qkv.weight`, `blk.0.ssm_out.weight`, `blk.0.ffn_down.weight`, and the last quantized tensor. Rows and block offsets include beginning/middle/end positions. Tensor name, shape, row, block, and absolute file offset are recorded.
- Actual files: `Ternary-Bonsai-2-27B-Abliterated-PQ2_0.gguf` (7,206,168,928 bytes) and `Ternary-Bonsai-2-27B-PTQ1_0.gguf` (5,946,648,928 bytes). The script independently reads their GGUF directories. Only headers and the selected blocks are read; the entire models are neither loaded nor hashed.
- Every native result is finite. JSON roundtrips preserve all decoded FP32 bits, including negative zero.

**Excluded:** infinity/NaN half scales, exhaustive whole-block combinations, model-level inference, GPU behavior, Hadamard transforms, and grouped GDN permutations. Model-level correctness requires separate tests beyond these block fixtures.

## Reproduction (Windows x64, Python 3.11 or later)

Run from the repository root with the two exact source models in `models`. The CPU binary is a reference dependency only; `_native/` is ignored by Git.

```powershell
$fixtureDir = Join-Path $PWD 'NNtrain.Core.Tests/Fixtures/PrismQuantReference'
$nativeDir = Join-Path $fixtureDir '_native'
New-Item -ItemType Directory -Force -Path $nativeDir | Out-Null
$archive = Join-Path $nativeDir 'prism-cpu.zip'
Invoke-WebRequest -Uri 'https://github.com/PrismML-Eng/llama.cpp/releases/download/prism-b10743-adfffbe/llama-prism-b10743-adfffbe-bin-win-cpu-x64.zip' -OutFile $archive
if ((Get-FileHash -Algorithm SHA256 -LiteralPath $archive).Hash -ne 'd0b3016c9cc4bc1385de68be034adee570277ba952dd94292ba3888b7f18cc44') {
    throw 'Reference ZIP checksum mismatch'
}
Expand-Archive -LiteralPath $archive -DestinationPath (Join-Path $nativeDir 'cpu') -Force
python (Join-Path $fixtureDir 'generate.py') `
  --pq-model '.\models\Ternary-Bonsai-2-27B-Abliterated-PQ2_0.gguf' `
  --ptq-model '.\models\Ternary-Bonsai-2-27B-PTQ1_0.gguf'
```

The generator uses Python's standard library and the native DLL. It checks native type sizes/block sizes, the pinned DLL hash, the reported reference commit, every field's coverage, all 38,400 values, and their signed-zero bit patterns. It never launches GPU work or a 27B forward pass. Identical model headers/blocks and reference DLL produce identical JSON.

Fixture SHA256 at creation: `6b6456d2bc40f0e35ea95e6179bff675ecca6c2374ff651b86ec30ed8f44f8bc` (393,459 bytes).
